# Data Model: Renderer Microservice (F011)

**Phase**: 1 — Design
**Date**: 2026-02-14

---

## Overview

The renderer microservice has **no database**. All state is held in an in-memory `Map<jobId, RenderJob>`. There are no persistent entities — on process restart, all job history is lost (acceptable for MVP).

The renderer receives a `RenderJobPayload` from the main app, processes it, and calls back. The shared types that define the payload are copied from the main app's `src/types/` into `renderer/src/types/`.

---

## Entities

### `RenderJob` (in-memory only)

Represents a single render job tracked in the in-memory job map.

```
RenderJob {
  jobId:        string    — UUID, generated by renderer on POST /render
  videoId:      string    — UUID from main app (from RenderJobPayload.videoId)
  userId:       string    — Clerk user ID (from RenderJobPayload.userId)
  status:       JobStatus — current lifecycle state
  stage:        JobStage  — current pipeline step
  progress:     number    — 0–100 (render % from Remotion onProgress)
  createdAt:    Date      — when job was accepted
  completedAt:  Date?     — when job finished (success or failure)
  error:        string?   — human-readable error if status === "failed"
}
```

#### Status State Machine

```
queued
  │
  ▼
processing ──────────────────────────────► failed
  │  (any error at any stage)
  ▼
completed
```

- `queued` → `processing`: immediately when async processing begins
- `processing` → `completed`: after successful Supabase upload + callback
- `processing` → `failed`: on any unrecoverable error in the pipeline
- There is no `canceled` state in MVP

#### Stage Progression

```
queued → download → bundle → render → upload → done
```

| Stage | Description |
|-------|-------------|
| `queued` | Job accepted, not yet started |
| `download` | Downloading images and audio from Supabase signed URLs |
| `bundle` | `@remotion/bundler` creating webpack bundle (uses cached bundle if available) |
| `render` | `@remotion/renderer` rendering frames via headless Chromium + FFmpeg |
| `upload` | Uploading rendered MP4 to Supabase Storage |
| `done` | Pipeline complete, callback fired |

Note: If the bundle is cached from a previous job, the `bundle` stage completes nearly instantly.

### `RenderJobPayload` (inbound from main app — shared type)

Defined in `src/types/render.ts` (main app) and copied to `renderer/src/types/render.ts`.

```
RenderJobPayload {
  videoId:          string         — UUID
  userId:           string         — Clerk user ID
  audioUrl:         string         — Signed Supabase URL for MP3 (1hr expiry)
  scenes:           RenderScene[]  — 3–5 scenes, ordered
  captionStyle:     CaptionStyle   — "word-by-word" | "full-sentence" | "none"
  transitionType:   TransitionType — "fade" | "crossfade"
  showWatermark:    boolean        — true for free-tier users
  callbackUrl:      string         — POST /api/video/render/complete URL
  stageCallbackUrl: string         — POST /api/video/render/stage URL
}
```

### `RenderScene` (part of RenderJobPayload — shared type)

```
RenderScene {
  sceneNumber:      number           — 1-based scene index
  imageUrl:         string           — Signed Supabase URL (1080×1920)
  durationInFrames: number           — Pre-calculated from audio alignment
  startFrame:       number           — Global start frame in composition
  wordTimings:      WordFrameTiming[] — Per-word frame timings (global frames)
}
```

### `WordFrameTiming` (shared type)

```
WordFrameTiming {
  word:        string — The word text
  startFrame:  number — Global frame (from composition start, frame 0)
  endFrame:    number — Global frame (from composition start, frame 0)
}
```

**Note**: WordFrameTiming values are GLOBAL (absolute) frames. The `VideoComposition` component subtracts `scene.startFrame` to convert to scene-local frames before passing to `WordByWord` / `FullSentence` caption components.

---

### `VideoCompositionProps` (passed to Remotion `renderMedia()` — shared type)

Defined in `src/types/remotion.ts`, copied to `renderer/src/types/remotion.ts`.

```
VideoCompositionProps {
  audioUrl:       string       — LOCAL file:// path (after download from Supabase)
  scenes:         RenderScene[] — Same as RenderJobPayload.scenes
  captionStyle:   CaptionStyle
  transitionType: TransitionType
  showWatermark:  boolean
}
```

**Important**: `audioUrl` in `VideoCompositionProps` is a local `file://` path (the downloaded temp file), NOT the signed Supabase URL from the payload. The renderer downloads the audio first, then passes the local path.

## Callback Payloads (outbound to main app)

### Completion callback body (POST to `callbackUrl`)

```
RenderCompleteCallback {
  videoId:         string  — UUID
  status:          "completed" | "failed"
  outputUrl:       string?  — Supabase signed URL for the MP4 (1hr) when completed
  fileSizeBytes:   number?  — MP4 file size in bytes when completed
  durationSeconds: number?  — Video duration in seconds when completed
  error:           string?  — Human-readable error message when failed
}
```

### Stage update body (POST to `stageCallbackUrl`)

```
RenderStageCallback {
  videoId: string
  stage:   "sync" | "render" | "finalize"   — maps to: download→"sync", render→"render", upload→"finalize"
}
```

Note: The stage callback mapping aligns with the main app's `RenderStage` type from F008 (`"audio" | "sync" | "render" | "finalize"`), which drives the progress UI. Renderer sends: `download` → fires `"sync"`, `render` → fires `"render"`, `upload` → fires `"finalize"`.

## Shared Files: Copy Strategy

These files are **copied** (not symlinked) from `src/` to `renderer/src/` during scaffolding:

| Source (main app) | Destination (renderer) | Notes |
|-------------------|------------------------|-------|
| `src/types/remotion.ts` | `renderer/src/types/remotion.ts` | VideoCompositionProps |
| `src/types/render.ts` | `renderer/src/types/render.ts` | RenderJobPayload, RenderScene, etc. |
| `src/types/scene.ts` | `renderer/src/types/scene.ts` | CaptionStyle, TransitionType |
| `src/remotion/Root.tsx` | `renderer/src/remotion/Root.tsx` | Remotion entry point |
| `src/remotion/VideoComposition.tsx` | `renderer/src/remotion/VideoComposition.tsx` | Main composition |
| `src/remotion/Scene.tsx` | `renderer/src/remotion/Scene.tsx` | Ken Burns scene |
| `src/remotion/captions/WordByWord.tsx` | `renderer/src/remotion/captions/WordByWord.tsx` | |
| `src/remotion/captions/FullSentence.tsx` | `renderer/src/remotion/captions/FullSentence.tsx` | |
| `src/remotion/transitions/Fade.tsx` | `renderer/src/remotion/transitions/Fade.tsx` | |
| `src/remotion/transitions/Crossfade.tsx` | `renderer/src/remotion/transitions/Crossfade.tsx` | |
| `src/remotion/utils/timing.ts` | `renderer/src/remotion/utils/timing.ts` | |
| `src/lib/constants/video.ts` | `renderer/src/lib/constants/video.ts` | VIDEO_FRAME_RATE etc. |

The `@/` alias in copied files maps to `renderer/src/` in the renderer's `tsconfig.json`.

## Environment Variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `PORT` | No | `3001` | HTTP port |
| `RENDER_WEBHOOK_SECRET` | Yes | — | Shared secret for `x-render-secret` header |
| `SUPABASE_URL` | Yes | — | Supabase project URL |
| `SUPABASE_SERVICE_KEY` | Yes | — | Service-role key (bypasses RLS) |
| `MAIN_APP_URL` | Yes | — | For reference only (callbacks use callbackUrl from payload) |
| `REMOTION_CONCURRENCY` | No | `2` | Parallel frame renderers in `renderMedia()` |
| `REMOTION_OUTPUT_DIR` | No | `/tmp/renders` | Temp directory for downloads and MP4 output |
| `PUPPETEER_EXECUTABLE_PATH` | No | auto | Path to Chromium binary (set in Dockerfile) |
